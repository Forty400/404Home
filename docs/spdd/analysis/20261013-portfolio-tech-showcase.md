# Analysis · 作品集向：用现有资产向前端大佬展示工程力

- Date: 2026-10-13
- Author: AI（8 年产品视角）+ user
- Status: done
- Related canvas: `docs/spdd/canvases/20261013-portfolio-tech-showcase.md`（active）

## 1. Problem

当前仓库已有较完整的 **SPDD 四层资产 + 404Home 产品代码**，但对「前端技术负责人 / Staff 面试官」的叙事不清晰：

- 外表面像 **AI 工具导航 CMS**，内核其实在长 **认证 / 钱包分账 / AI 代理计费 / AI 协作工程体系**。
- 文档资产密度高，但 **可演示的技术深度面**（性能、类型安全、可测性、现代 DX、复杂前端状态）尚未对齐到面试官 5–15 分钟扫库的注意力预算。
- 若不做刻意包装与迭代，面试官容易判成「内容站 + Vue CLI CRUD」，低估真实工程决策能力，错失高薪前端 / 全栈前端 offer 的议价点。

不做会怎样：资产继续「对内可用、对外不可读」；简历只能写「做过导航站」，无法证明 Staff 级判断力。

## 2. Goals / Non-goals

**Goals**

- 把现有资产重定位为 **「可审查的工程作品集」**：3 分钟看懂故事，15 分钟能追到 ADR/测试/代码锚点。
- 用 1–2 个 **高信号技术切片**（而非铺全站功能）证明前端/全栈前端能力上限。
- 明确迭代优先级：先「展示面」与「证据链」，再「业务功能广度」。
- 给出可验收的作品集门槛（见 §7 建议画布的验收意图）。

**Non-goals**

- 不为求职专门重写一套无关 Demo（不另起玩具项目）。
- 不在本分析阶段改生产代码或选型落地（决策进 ADR + 画布后再做）。
- 不把 SPDD 文档本身当成对外主叙事（对内是护城河，对外是附录）。
- 不承诺「做完必拿 offer」；只优化可被资深前端读懂的证据质量。

## 3. Users & Scenarios

| Actor | Scenario | Success |
| --- | --- | --- |
| 前端 Tech Lead / 面试官 | 打开仓库或线上 Demo，扫 README → 点 Trial → 翻 1–2 个 ADR | 5 分钟内说出「这人会做鉴权隔离、计费边界、契约驱动、可测代码」 |
| 用户本人（求职） | 面试讲项目 | 能用「问题 → 取舍 → 验收 → 代码」讲 3 个深故事，而非功能清单 |
| 同行前端大佬 | 被分享链接 / 内推预审 | 愿意追问架构，而不是只夸「页面挺全」 |
| 未来的自己 / AI | 继续迭代 | 有明确「作品集切片」优先级，避免功能蔓延稀释信号 |

## 4. Constraints

- Tech: 现状为 Vue 3 + Vue Router + Vue CLI；Koa + SQLite；测试栈刚定（vitest + node:test），覆盖仅 auth P0。
- Time: 求职窗口有限，迭代必须 **高 ROI、可演示、可讲清**；忌同时迁移栈 + 铺微信/支付。
- Ops / security: Demo 环境不可泄露 DeepSeek Key / SSH；演示账号与额度需可控防刷。
- Brand: 保持 404Home 既有视觉语言，避免「紫霓虹 AI 模板脸」。

## 5. Risks

| Risk | Impact | Mitigation |
| --- | --- | --- |
| 继续堆 CMS/资讯功能 | 信号被稀释，看起来像运营站 | 作品集期冻结低信号功能；优先 Trial / 钱包 / 工程证据 |
| 只补文档不补可运行证据 | 大佬认为「会写 Markdown」 | 每个主张绑定：线上路径 + 测试用例 + ADR |
| 为简历强上 TS/Vite/微前端 | 半吊子迁移反成减分 | 一次只做一个有 ADR 的现代化切片，并写清为何不做更大 |
| Demo 不稳定 / 无数据 | 面试翻车 | 固定 Demo 脚本 + seed 演示账号 + 健康检查 |
| 过度强调 AI 写代码 | 被认为「不会手搓」 | 叙事重点放在决策与边界，AI 协作是加速器不是主角 |

## 7. 现状资产诊断（产品视角）

### 7.1 资产盘点（你已有的「库存」）

| 层 | 现状 | 对资深前端的信号强度 |
| --- | --- | --- |
| 产品代码 `404home` | 导航 CMS + Admin + AuthModal + Trial 壳 + 钱包/会话后端能力在长 | **中**：功能面宽，深度集中在少数模块 |
| `2-adr决策` | 资产分层、回填、测试栈、登录缓存等 | **高**：证明会做取舍（但需人引导去读） |
| `3/4 测试*` | 九模块边界/条例齐全；自动化仅 auth 首批 | **中高潜力 / 现执行弱**：文档超前于代码是双刃剑 |
| `1-资产规范` | 架构/认证/钱包/主题等模块化规范 | **高（对内）**：对外需浓缩成 1 页「设计原则」 |
| `canvases` + `analysis` | DeepSeek 试用路线完整；P0/P1/P2 切片清晰 | **高**：可直接变成面试故事线 |
| RAG / Skills / Rules | AI 协作闭环可运行 | **差异化**：讲「人机协作工程化」加分，别当唯一卖点 |
| README / 演示叙事 | 偏内部工程说明 | **低**：缺对外故事与「先看哪里」 |

### 7.2 资深前端实际在验什么（对照缺口）

| 他们验的能力 | 你现在能举证的 | 明显缺口 |
| --- | --- | --- |
| 复杂交互与状态边界 | AuthModal、深链、主题、试用页 | 缺「会话流 + 余额实时一致性」完整闭环演示 |
| 工程化与质量门 | `npm test`、条例编号对齐 TC | 覆盖窄；无组件测/E2E；CI 未成为对外徽章 |
| 架构判断 | 双角色 JWT、分账、Key 不进前端 | 缺公开 Architecture / Decision 入口页 |
| 现代前端栈敏感度 | Vue 3 Composition | Vue CLI 偏旧；无 TS；无明确性能/可访问性故事 |
| 产品感与完成度 | 导航站信息架构完整 | 作品集主角应是 Trial/计费，而非工具列表 |
| 安全意识 | 密码不进 localStorage（ADR） | 需可演示 + 可引用测试断言 |

### 7.3 关键洞察（给迭代定调）

1. **你的真正差异点不是「又一个 AI 导航」**，而是：用 SPDD 把 **计费型 AI 试用** 做成可审查契约，并有 ADR/测试落地——这在同级作品集里稀缺。
2. **资产已经「对内过重、对外过轻」**：继续回填九模块文档的边际收益低于打磨 2 个「可点击证据链」。
3. **高薪前端 offer 买的是判断力与可交付复杂度**，不是页面数量。冻结低信号功能 = 产品策略，不是偷懒。

## 8. 迭代策略：作品集三层漏斗

```text
L1 钩子（30s）  线上 Demo：登录 → 试用对话 → 余额变化
L2 证据（15m）  README「先看」→ 3 个 ADR → 对应测试 → 代码锚点
L3 深度（面试） SPDD 闭环 + 钱包分账 + 角色隔离 + AI 代理边界
```

### 阶段 A · 叙事与入口（约 0.5–1 天，最高 ROI）

- 写对外 README（或 `docs/portfolio.md`）：一句话定位、架构一图、**先看路径**、技术亮点 5 条、非目标。
- 明确作品集主角：**DeepSeek 试用（认证 + 钱包 + 代理）**；导航 CMS 降为「宿主/背景」。
- 准备 3 个面试故事（问题/选项/决策/后果），直接锚定已有 ADR/画布：
  1. 双角色 JWT 与禁止冒充
  2. 金额用分 + 账本、禁止裸改余额
  3. 登录缓存只存邮箱（安全取舍）

### 阶段 B · 闭合一条「高薪信号」业务切片（约 3–7 天）

优先闭合 **可演示的 Trial 计费闭环**（比微信登录更吃香）：

- 未登录拦截 → 弹窗登录 → 服务端代理模型 → 扣费入账 → UI 余额刷新 → 余额不足可读错误码。
- 自动化：把 wallet/chat 的 P0 条例落到 `npm test`（延续 `ADR-20261013-test-stack`）。
- 可选：一条最小 Playwright「登录到扣费」作为对外质量徽章。

验收标准（产品）：

- [ ] 陌生人按 README 5 步能走完「注册→对话→余额变少」。
- [ ] 每个亮点都能指到：规范段落 + ADR + 至少 1 条自动化用例。
- [ ] Demo 有固定演示账号与额度恢复方式。

### 阶段 C · 一个「现代化」显性工程故事（约 3–5 天，二选一深做）

只选一个做透并写 ADR（避免同时开坑）：

| 选项 | 信号 | 风险 |
| --- | --- | --- |
| C1. Vue CLI → Vite + 明确目录边界 | 现代 DX、构建认知 | 迁移噪音 |
| C2. 关键路径补 TypeScript（composables/api） | 类型纪律、可维护性 | 半迁移更糟，需划边界 |
| C3. 性能故事：路由懒加载、关键资源、Lighthouse 基线写入规范 | 前端专业度 | 需可复现数据 |

推荐默认：**C1 或 C3**（对前端大佬更「一眼现代」）；TS 适合作为阶段 D。

### 阶段 D · 差异化加分（有余力）

- 公开精简版「工程手册」：SPDD 四层一张图 + 一次真实 `spdd-sync` 漂移案例。
- Theme 系统作为 UI 工程小品（CSS 变量 + `data-theme`），不要当主菜。
- 微信/支付：商业完整度加分，但求职窗口内 **优先级低于 B+C**。

## 9. 刻意不做（作品集窗口）

- 资讯/教程内容运营扩张
- 多模型路由、Agent 市场、微前端
- 为「看起来忙」批量新增模块规范而无代码/测试
- 把管理后台 CRUD 当作面试主线
